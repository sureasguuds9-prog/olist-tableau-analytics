# Olist в Yandex DataLens: пошаговая сборка дашборда

Эта инструкция позволяет собрать готовый портфельный дашборд Olist в Yandex DataLens без SQL и без объединения исходных таблиц. Все расчёты уже выполнены в Python, поэтому в DataLens загружаются шесть небольших аналитических витрин из папки `datalens/data/`.

## Что получится в конце

Дашборд из четырёх вкладок:

1. **Главное** — основные KPI, динамика GMV и заказов, ведущие категории.
2. **Продажи** — GMV, средний чек и показатели категорий.
3. **Клиенты** — когортный retention и RFM-сегменты.
4. **Доставка** — опоздания, сроки доставки и плохие отзывы.

Ориентировочное время сборки: 2–3 часа при первом знакомстве с DataLens.

## Шаг 1. Создать воркбук

1. Откройте [Yandex DataLens](https://datalens.yandex.ru/).
2. В левой панели выберите **Коллекции и воркбуки**.
3. Нажмите **Создать воркбук**.
4. Назовите его `Olist E-commerce Analytics`.
5. Откройте созданный воркбук.

Внутри одного воркбука будут храниться подключение, шесть датасетов, чарты и итоговый дашборд.

---

## Шаг 2. Загрузить CSV

1. В воркбуке нажмите **Создать → Подключение**.
2. В разделе **Файлы и сервисы** выберите **Файлы**.
3. Нажмите **Загрузить файлы**.
4. Выберите сразу все шесть CSV из папки `datalens/data/`.
5. Для каждого файла проверьте параметры:
   - кодировка — `UTF-8`;
   - разделитель — `Запятая`;
   - заголовки столбцов — `Да`.
6. Нажмите **Создать подключение**.
7. Сохраните его в воркбук `Olist E-commerce Analytics` под названием `Olist CSV marts`.

DataLens позволяет держать до 10 файлов в одном файловом подключении, поэтому все шесть витрин помещаются в одно подключение.

## Шаг 4. Добавить корректные показатели доставки

`delivery_quality.csv` агрегирован до уровня «штат × статус доставки». Простое `AVG(bad_review_share)` даст невзвешенное среднее по штатам. Чтобы крупный и маленький штат не имели одинаковый вес, создайте в датасете `06 Olist — Доставка` четыре вычисляемых поля.

Нажмите **Добавить поле** и последовательно создайте:

### Доля плохих отзывов, взвешенная

```text
SUM([bad_review_share] * [orders]) / SUM([orders])
```

Тип отображения: проценты, два знака после запятой.

### Средняя оценка, взвешенная

```text
SUM([average_review] * [orders]) / SUM([orders])
```

### Средний срок доставки, взвешенный

```text
SUM([average_delivery_days] * [orders]) / SUM([orders])
```

### Доля опозданий

```text
SUM_IF([orders], [delivery_status] = "С опозданием") / SUM([orders])
```

Тип отображения: проценты, два знака после запятой.

Сохраните датасет после добавления формул.

## Шаг 11. Оформление

Используйте простую единую палитру:

- основной цвет продаж — синий `#2F80ED`;
- положительный показатель — зелёный `#27AE60`;
- опоздания и плохие отзывы — красный `#EB5757`;
- нейтральные элементы — серый `#828282`;
- фон — белый или очень светло-серый.

Правила оформления:

- не используйте 3D-графики;
- подписывайте единицы: `R$`, `%`, дни, заказы;
- показывайте не более 10–15 категорий на одном графике;
- ставьте легенду только там, где цвет несёт смысл;
- не обрезайте ось у графиков с долями так, чтобы разница выглядела искусственно большой;
- оставьте таблицы в нижней части вкладки.

## Шаг 12. Финальная проверка

До публикации проверьте:

- [ ] загружены ровно шесть подготовленных CSV;
- [ ] создано шесть отдельных датасетов без связей между таблицами;
- [ ] `purchase_month` и `cohort_month` распознаны как даты;
- [ ] доли и retention отображаются в процентах, а не как числа от 0 до 1;
- [ ] GMV равен `15 419 773,75`;
- [ ] доставленных заказов `96 478`;
- [ ] уникальных клиентов `93 358`;
- [ ] доля повторных клиентов `3,00%`;
- [ ] доля опозданий `8,11%`;
- [ ] нулевой месяц каждой когорты равен `100%`;
- [ ] плохие отзывы: вовремя около `9,19%`, с опозданием около `53,99%`;
- [ ] селекторы не фильтруют чарты из несовместимых датасетов;
- [ ] названия и подписи на русском языке;
- [ ] все четыре дашборда открываются без ошибок.

Если контрольные значения не совпадают, сначала проверьте фильтры, агрегацию поля и отсутствие соединений между витринами.

## Шаг 13. Опубликовать и добавить в GitHub

1. Откройте каждый итоговый дашборд.
2. Нажмите меню доступа и выберите **Поделиться**.
3. Перейдите на вкладку **Публичный**.
4. При необходимости включите публичный доступ для дашборда и связанных объектов.
5. Скопируйте публичную ссылку; если публичный доступ не нужен, сохраните рабочую ссылку с пометкой о необходимости авторизации.
6. Добавьте ссылки на четыре страницы в `datalens/README.md`.
7. Если включён публичный доступ, откройте ссылки в режиме инкогнито и убедитесь, что страницы доступны без авторизации.

Перед публикацией убедитесь, что в данных нет персональных или закрытых сведений. Подготовленные витрины Olist содержат только агрегированные показатели.

## Как обновить данные

Если исходные CSV были заменены:

1. Из корня проекта снова выполните:

```bash
python datalens/prepare_datalens_data.py
```

2. В подключении `Olist CSV marts` для каждого файла выберите **Заменить**.
3. Загрузите новый CSV с тем же названием и структурой.
4. Нажмите **Сохранить изменения**.
5. Проверьте контрольные KPI на дашборде.

При сохранении названий и типов столбцов существующие датасеты и чарты продолжат работать.

## Частые ошибки

| Проблема | Причина | Что сделать |
|---|---|---|
| Дата отображается текстом | неверный тип поля | изменить тип на `Дата` в датасете |
| Вместо 3% показано 0,03 | числовой формат | выбрать отображение в процентах |
| GMV стал в несколько раз больше | таблицы были соединены | удалить связи и использовать отдельные датасеты |
| Доля плохих отзывов не совпадает | применено простое среднее по штатам | использовать взвешенное вычисляемое поле |
| KPI-карточка суммирует все метрики | нет фильтра `metric` | оставить в фильтре карточки только одну метрику |
| Селектор не влияет на график | разные датасеты или не настроена связь | проверить источник и связь селектора с виджетом |
| Ретеншн больше 100% | неверная агрегация или соединение | использовать `AVG(retention)` без связей таблиц |
